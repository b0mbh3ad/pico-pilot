# PicoPilot

Неофициальный пульт для шлемов Pico с Android-телефона. Работает по Wi-Fi без ПК, аккаунтов и облака: всё общение идёт напрямую между телефоном и шлемом в вашей локальной сети.

Состоит из двух частей:

| Что | Где | Зачем |
|---|---|---|
| **PicoPilot** | телефон | Пульт: громкость, яркость, экран, приложения, терминал, логи |
| **PicoPilot Агент** | шлем | Приёмник подключений. Сам объявляет себя в сети и выполняет команды |

## Как это работает

Раньше телефон цеплялся к шлему через ADB по Wi-Fi. Это требовало включённой отладки, подтверждения ключа и после сна шлема ломалось до перезагрузки.

Теперь на шлеме работает маленький агент — аналог USB-донгла беспроводной мыши:

1. Агент слушает UDP-порт `47800` и отвечает на поисковые запросы.
2. Телефон рассылает запрос по всей подсети и собирает ответы: «я Pico, вот мой IP и порт».
3. Дальше телефон подключается по TCP (`47801`), один раз вводит PIN и работает.
4. Если шлем заснул или Wi-Fi отвалился — телефон сам переподключается, когда сеть вернётся. Перезагружать шлем не нужно.

Протокол — JSON-строки поверх TCP, двоичные данные (скриншоты, APK, видео) передаются кусками в base64. Никаких сторонних серверов.

### PIN

Агент показывает 6-значный PIN. Он вводится в телефоне один раз и запоминается. PIN можно сменить кнопкой «Новый PIN» — тогда телефон попросит его заново. Это защита от того, чтобы любой человек в той же Wi-Fi сети не получил root-shell на шлеме.

### Root

Если на шлеме есть root (Magisk, KernelSU, встроенный `su`), агент автоматически его находит и выполняет команды от root. Без root работают только команды, доступные обычному приложению: громкость и часть настроек будут недоступны.

## Возможности

**Подключение**
- Автоматический поиск шлемов с агентом по всей подсети.
- Ввод PIN, запоминание, автоподключение к последнему шлему.
- Резервный режим ADB (порт 5555) — если агент недоступен.

**Определение модели**
- Автоопределение по `getprop` (Pico 4 Ultra, 4 Pro, 4, Neo 3, Neo 2, G3, G2, Pico 5 и др.).
- Ручной выбор модели, если эвристика ошиблась.
- Показ «сырых» параметров: модель, устройство, Android, PICO OS, сборка, серийник, fingerprint.

**Управление**
- Громкость: слайдер, ±1, mute.
- Яркость экрана шлема.
- Отправка текста в активное поле шлема.
- Перезагрузка, выключение, перезагрузка в recovery.

**Экран**
- Скриншот: весь стереокадр или только левый/правый глаз (Pico отдаёт два глаза рядом).
- Сохранение в галерею и отправка «Поделиться».
- Запись экрана в MP4 (до 3 минут) с сохранением на телефон.

**Приложения**
- Список пользовательских или всех приложений, поиск по пакету.
- Запуск, принудительная остановка, очистка данных, удаление.
- Установка APK прямо в шлем: файл заливается агенту и ставится через `pm install`.

**Инструменты**
- Терминал: любая shell-команда на шлеме + быстрые команды.
- Живые логи logcat с фильтрами E/W/I/D, поиском, паузой и автоскроллом.
- Сброс ADB-ключа для резервного режима.

## Установка

### 1. Агент на шлем

Файл: `PicoPilot-Agent-1.1.apk` (или `agent/build/outputs/apk/debug/agent-debug.apk`).

Способы:

- **По USB с ПК:** подключить шлем кабелем, включить «Отладка по USB» и выполнить
  ```
  adb install -r PicoPilot-Agent-1.1.apk
  ```
- **Через сам PicoPilot:** «Ещё → Приложения → Установить APK» (это работает и по агенту, и по ADB).
- **Файловым менеджером на шлеме:** скопировать APK в память шлема и открыть.

После установки открыть **PicoPilot Агент**, оставить его включённым. Кнопка «Разрешить работу в фоне» снимает ограничения энергосбережения. «Запускать при включении шлема» включает автозапуск после перезагрузки.

### 2. Приложение на телефон

Файл: `PicoPilot-1.3.apk` (или `app/build/outputs/apk/debug/app-debug.apk`).

Скопировать на телефон, открыть в проводнике, разрешить установку из неизвестных источников. APK подписан отладочным ключом.

> Windows не запускает `.apk` ни двойным кликом, ни через Win+R — это файл для Android, его нужно ставить на телефон.

### 3. Подключение

1. Телефон и шлем — в одной Wi-Fi сети (VPN на телефоне выключить).
2. В PicoPilot нажать **«Найти шлем»**.
3. Выбрать шлем в списке, ввести PIN с экрана шлема.
4. Готово. Дальше подключение происходит само.

## Резервный режим ADB

Если агент установить нельзя, остаётся старый путь:

1. На шлеме: **Настройки → О системе → 7 раз тапнуть по номеру сборки**.
2. **Настройки → Для разработчиков → Отладка по USB**.
3. Один раз подключить шлем к ПК и выполнить `adb tcpip 5555`.
4. В PicoPilot переключить режим на **ADB**, ввести IP, подключиться и подтвердить отладку в шлеме.

Ограничения ADB-режима: после перезагрузки отладку иногда нужно включать заново, а после сна шлема ADB не поднимается до перезагрузки. Именно поэтому основной режим — агент.

## Сборка из исходников

Нужен JDK 21 и Android SDK с платформой 34.

```powershell
$env:JAVA_HOME="$env:USERPROFILE\.jdks\jbr-21.0.11"
.\gradlew.bat :app:assembleDebug :agent:assembleDebug
```

Готовые файлы:
- `app/build/outputs/apk/debug/app-debug.apk`
- `agent/build/outputs/apk/debug/agent-debug.apk`

Gradle 8.7, AGP 8.5.2, Kotlin 2.0.21, Jetpack Compose (BOM 2024.09.03), compileSdk 34. Агент без Compose и без внешних зависимостей — маленький APK.

> В `gradle.properties` включён `android.overridePathCheck=true`, потому что путь к проекту содержит кириллицу. На слабых машинах уменьшены лимиты памяти Gradle/Kotlin.

```

├── ui/         тема, компоненты, экраны, навигация
└── util/       сохранение скриншотов/видео в MediaStore

agent/src/main/java/com/picopilot/agent/
├── MainActivity.kt   экран агента: статус, IP, PIN, журнал

```

## Ограничения и предупреждения

- Это неофициальное приложение, не связанное с Pico/Bytedance.
- «Сон» и «пробуждение» убраны намеренно: при уходе в сон Pico отключает Wi-Fi. По ADB шлем не разбудить, а агент после возврата Wi-Fi просто снова доступен.
- Определение модели эвристическое: коды моделей и наборы свойств отличаются между прошивками. Если модель определилась неверно — выберите её вручную на экране «Модель и параметры».
- `screenrecord` на части прошивок Pico пишет чёрный экран — ограничение системы.
- Удаление системных приложений и очистка данных могут привести к сбоям шлема. Делайте это осознанно.
- Команды выполняются от root, если root есть. Это полный доступ к системе шлема — PIN агента не сообщайте посторонним.
- Приложение не отправляет данные наружу: PIN и настройки лежат только в SharedPreferences на телефоне и шлеме.

## Если не подключается

- В списке «Шлемы рядом» пусто: проверьте, что агент запущен на шлеме, телефон в той же Wi-Fi сети и на роутере выключена изоляция клиентов.
- «Неверный PIN»: посмотрите PIN в приложении агента на шлеме и введите заново.
- Шлем не отвечает после сна: подождите несколько секунд, телефон переподключится сам.
- Если агент не ставится: проверьте, разрешена ли установка из неизвестных источников, и что APK собран под Android 8.0+.
- ADB-режим: порт 5555 должен быть открыт (`adb connect IP:5555`), VPN на телефоне выключен.
